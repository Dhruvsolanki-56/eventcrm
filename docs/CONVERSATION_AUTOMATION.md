# Conversation-first email workflow

Gather keeps one person under one company and adds a new conversation for each later meeting. A conversation may be linked to an event, including an expo, or left as another meeting. The person page shows the dated history and event label. The capture page asks which event should receive new photos or QR results before upload, so event analytics and later email context have the right attribution.

The fast path is capture → immediate local OCR → one-at-a-time review → save under the existing or a new person → optionally prepare an editable email. A repeat upload of the exact same image bytes, or repeat QR contact fields, reuses an accessible stored scan instead of writing another scan. A saved repeat directs the user to add a conversation to that person. Separately, matching email or phone during review asks the user to link to the existing person; it does not silently merge uncertain identities. One company can still have many people. These are exact-match/idempotency protections, not a guarantee that crops, retakes, changed QR contents, typos, or concurrent uploads can never duplicate data. No existing scan hashes were backfilled by this change.

On the person page, **Add conversation** records the exchange without another contact. **Add & prepare email** does the same and prepares a new draft; nothing is sent until the user presses **Send email**. Repeated submission with the same request ID reuses the saved conversation. If a draft is already open, the UI asks before replacing it on screen; the earlier server-side draft remains unsent. The draft uses the newest accessible conversation first and up to five older accessible entries for continuity. Its visible sources show the latest three. Event access still limits which history a member can see and use for a draft. Older topics are context, not evidence that they came up at the latest event.

Voice recording and saved voice-note text remain linked to the chosen conversation. The user can ask for on-device Whisper Tiny transcription before attaching a new recording or on the person page after saving one. The model downloads from Hugging Face on first use, then speech inference runs in the browser without sending the audio to that model host. The result is an editable suggestion, not an automatic saved fact; only checked text the user saves can inform an email draft. Accuracy and speed vary by device and language, and a local transcription does not independently understand or summarize the conversation. The email-draft prompt treats saved text as unverified context.

Card reading starts on upload. With no card API selected, local OCR handles it. With a Gemini API key configured and the user opting in on Capture, Gemini reads each new photo immediately after upload; local OCR is the fallback when the free tier is unavailable. **Ask AI to check this photo** remains an explicit second pass on Review. Gemini free-tier calls are limited and Google may use content to improve its products, so obtain permission before submitting private cards. The API may suggest fields but cannot save or send for the user. No real-card accuracy rate or live-provider success has been established by the synthetic fixture tests. Verify all fields before saving.

## What is not automated yet

There is no unattended lead-email sequence, scheduled lead send, reply detection from a mailbox, consent registry, suppression policy for a campaign, or automatic personalization from raw audio. Daily digests are reminders to the signed-in user, not lead campaigns. Turning this into unattended tenant-scoped sending needs a defined trigger, recipient consent/opt-out rules, delay and quiet hours, stop-on-reply behavior, approval policy, per-tenant limits, and provider/bounce handling. The current explicit-send boundary is intentional until those rules are specified and tested. A configured SMTP server accepting a message does not prove inbox delivery.

## Local verification (2026-10-02)

- Production build and no-provider smoke passed; unit tests: 46/46 after the card-API and local-voice changes.
- An opt-in synthetic browser test downloaded the Whisper Tiny model, produced a nonempty local transcript, and confirmed it was not saved automatically. A mocked card-API browser test confirmed opt-in upload-to-review at desktop and phone widths. No real Gemini key or real-card accuracy evaluation was available.
- Main browser suite after this change: 42 passed, 13 intentionally skipped because specialized quota and provider/model-download tests run separately. Full control crawl previously passed 4/4, covering 570 distinct controls at 1440 px and 390 px with no undersized phone tap targets; it has not been rerun after the two new transcription controls.
- No-provider OCR: 5/5; local SMTP fixture: 12/12; QR quota: 1/1. The conversation continuity regression checks event analytics, idempotent retries, denied cross-event writes, exact image/QR reuse, and unsent email drafts.
- In the main browser suite, one fixture photo reached review-ready in 1,745 ms and five in 9,399 ms. These are local test-reader measurements, not real-card accuracy or a live-provider latency guarantee. A bundled synthetic brochure still needed a human company-name correction; this is why review remains mandatory.
